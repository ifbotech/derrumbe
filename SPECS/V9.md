## 2. Celdas

### Celda: reglas-balance
Eres Reglas-Balance. Lee `.claude/agents/reglas-balance.md`. Sala: `Reglas-Balance`. Solo tocas `src/rules/`, `scripts/analyze-meta.ts`, `scripts/lab.ts`, `scripts/meta-report.json` y `tests/`.

1. **`src/rules/balance-config.json`.** Reúne en un único JSON los números de balance: `STAGES` (amenazas, cantera), `FATIGUE`, valores numéricos de herramientas (los que hoy están en el primer elemento de `desc` y en los efectos), niveles de obra y barajas. Los textos `desc` se generan a partir de esos números con una función pura, para que texto y valor no se separen. El motor lee el JSON (comprueba que `tsconfig.json` admite `resolveJsonModule` y que `vite` y `esbuild` lo empaquetan).
2. **Esquema validado.** Escribe `tests/balance-config.test.ts`: comprueba tipos y rangos de cada campo, que `FATIGUE.every` sea 2, ≤ 6 palabras clave, ≤ 56 herramientas, descripciones ≤ 115 y que ningún valor haga imposible un objetivo (amenaza ≥ 1, etc.).
3. **Equivalencia exacta.** Antes de borrar los literales, una prueba compara el estado del motor con el JSON contra una instantánea de la V8 sobre 500 campañas sembradas: mismo resultado, jugada a jugada.
4. **Hash de estado.** Función pura `stateHash(view): string` (determinista, sin `Date` ni `Math.random`) para que el servidor y el cliente comparen resúmenes. Pruebas: dos vistas iguales dan el mismo hash, un cambio de una carta lo cambia.
5. **200 partidas cooperativas simuladas** con 2 a 4 jugadores y cortes aleatorios (script `scripts/simulate-coop.ts`, tuyo): cada corte se reconecta y el hash final coincide en todos los asientos.
6. Documenta el JSON con `npm run docs` (las tablas se generan, no se editan a mano).

Comprobación: `npm run typecheck`, `npm test`, informe completo del laboratorio (debe ser idéntico al de la V8), `npm run docs`. Informe: campos del JSON, resultado de la equivalencia y de las 200 partidas.

### Celda: juice-ux
Eres Juice-UX. Lee `.claude/agents/juice-ux.md`. Sala: `Juice-UX`. Para esta versión eres dueño también de `src/server/index.ts` y `src/client/net.ts`. No toques `src/rules/` ni la maquetación.

1. **Reconexión.** Quien pierde la conexión conserva su asiento 120 s. Al volver con `rejoin`, el servidor le envía el estado completo y la cola de eventos pendientes. Cliente: reintentos con espera creciente (1, 2, 4, 8 s, máximo 8 s) y aviso discreto «Reconectando…» (texto en `net.ts`, el estilo lo pinta `arte-ui`).
2. **Desincronización.** El servidor envía `stateHash` (de `src/rules`) con cada jugada; si el hash del cliente difiere, el cliente pide el estado y lo reemplaza. Nunca se confía en el cálculo del cliente.
3. **Telemetría anónima, apagada por defecto.** Módulo `src/client/telemetry.ts`: sin consentimiento guardado no existe ninguna petición de red. Con consentimiento, envía solo eventos agregados (resultado de obra, nivel, herramienta elegida, versión del juego) sin identificadores, sin IP guardada, sin texto libre y con un identificador de sesión aleatorio que no persiste. El punto de recogida es el que el usuario ponga en Ajustes (variable `telemetryUrl`); sin URL no se envía nada, aunque haya consentimiento.
4. **Consentimiento.** Pantalla propia con dos botones del mismo peso («Sí, enviar datos anónimos» y «No, gracias»), nunca marcada de antemano, que se puede revocar en Ajustes en cualquier momento. Revocar borra la clave `derrumbe:telemetry`.
5. **Prueba de humo.** `scripts/smoke.ts`: con la red bloqueada, el juego no hace ni una petición a `telemetryUrl`; tras cortar un asiento en cooperativo, vuelve a su sitio con el hash correcto; con consentimiento activado se envía exactamente un evento por obra.

Comprobación: `npm run typecheck` y `QA_DIR=dist/qa-juice npm run qa:smoke` con «Todo en orden». Informe: protocolo nuevo (mensajes), eventos de telemetría y enganches.

### Celda: arte-ui
Eres Arte-UI. Lee `.claude/agents/arte-ui.md`. Sala: `Arte-UI`. Eres dueño de `theme.css`, `styles.css`, `campaign.css`, `card.ts`, `art.ts`, `glyphs.ts`, `engraving.ts`, `table.ts`, `runscreens.ts`, `guild.ts`, `widgets.ts`, `home.ts`, `lobby.ts`, `lupa.ts`, `scripts/visual-qa.ts` y `qa.ts`.

1. **Pantalla de consentimiento** de telemetría (`consentimiento`): texto llano con qué se envía y qué no, dos botones iguales de ≥ 44 px, sin patrones oscuros, ≥ 13 px, sin recortes en las cuatro ventanas. Se enlaza desde Ajustes.
2. **Aviso «Reconectando…»** en la mesa y en la sala: una placa pequeña que no tapa la mano ni la cuenta, con estado accesible (`role="status"`).
3. **Sala cooperativa**: el asiento desconectado se muestra atenuado con su cuenta atrás de 120 s.
4. **Estados de QA** nuevos en `qa.ts`: `consentimiento`, `sala-reconectando`.

Comprobación: `npm run typecheck` y `QA_DIR=dist/qa-arte npm run qa:visual` con cero fallos; mira las capturas.

## 4. Fuera de alcance

Cuentas de usuario, tablas de clasificación, matchmaking, cambios de reglas o de números, cualquier dato que identifique a una persona. La telemetría no se activa nunca por defecto.
