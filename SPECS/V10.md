# V10 · Candidata a lanzamiento con funciones congeladas: accesibilidad, preparación para traducir y empaquetado para Steam / Tauri v2

Estado: planificada. Se ejecuta con `scripts/estudio-autonomo.ps1` sobre la rama `estudio/v10`, con las celdas una detrás de otra en el orden en que aparecen. **Congelación**: ninguna celda añade una función de juego. Vocabulario: el de CORONA ROTA (`SPECS/V6-normas-y-glosario.md` y `SPECS/V6-biblia-de-nombres.md`).

## 1. Tema y evidencia

**Tema.** Cero funciones nuevas: que lo pueda jugar cualquiera, que se pueda traducir sin tocar código y que se instale como un juego de escritorio.

| Evidencia | Número | Fuente |
|---|---|---|
| Auditoría visual | 25 estados × 4 ventanas en la QA de la 5.0, más los que sumen la V7, la V8 y la V9 | `scripts/qa.ts` |
| Constitución | ≤ 6 palabras clave, ≤ 56 reliquias (hoy 52), descripciones ≤ 115, P95 ≤ 19 | `tests/invariantes.test.ts` |
| Textos repartidos | nombres y descripciones en `src/rules/*.ts`; textos de pantalla como literales en `src/client/*.ts`: traducir obliga a tocar código | código |
| Distribución | solo web (GitHub Pages en `/derrumbe/`) y PWA | `README.md`, `manifest.webmanifest` |
| Steam Deck | estrato con la aprobación más baja de la V4 (11,1 %, n = 36); la ventana 1280×800 ya está en la QA | panel simulado V4; `scripts/visual-qa.ts` |
| Fatiga a las 4 h | lo que la V8 deje por encima de 4 | puerta de GPU de la V8 |

## 2. Celdas

### Celda: reglas-balance
Eres Reglas-Balance. Lee `.claude/agents/reglas-balance.md`. Sala: `Reglas-Balance`. Solo tocas `src/rules/`, `src/shared/i18n/` (nuevo, la parte de reglas), `scripts/analyze-meta.ts`, `scripts/lab.ts`, `scripts/reglas.ts`, `scripts/meta-report.json` y `tests/`.

1. **Congelación.** `tests/invariantes.test.ts` compara contra una lista guardada de identificadores (reliquias, especiales, monarcas, asaltos, Reinados, barajas, juramentos, atajos, secretos, palabras clave), generada con la V9: si la V10 añade o quita uno, falla.
2. **Catálogo de textos de reglas.** Todo `name`, `desc`, `who`, `label` y etiqueta de `step` de `src/rules` pasa a `src/shared/i18n/es.json` con claves estables (`reliquia.piqueta.nombre`, `monarca.intemperie.decreto`…). Los datos guardan la clave y una función pura `t(clave, valores)` devuelve el texto; las cifras entran como valores, nunca escritas dentro de la frase traducible. `tests/vocabulario.test.ts` pasa a recorrer el catálogo.
3. **Revisión de textos**: ortografía, tono y jerga en todo el catálogo de reglas. Solo texto, nunca un número. ≤ 115 caracteres.
4. **Errores**: las seis barajas con 1 a 4 jugadores en `scripts/simulate*.ts` con miles de semillas; informa de cualquier excepción o estado inalcanzable y arregla lo que sea del motor.
5. Si la V9 dejó una propuesta de autoajuste aprobada por el Director en esta especificación, aplícala aquí y solo aquí, con el laboratorio delante. Si no hay ninguna, el informe tiene que salir idéntico al de la V9.

Comprobación: `npm run typecheck`, `npm test`, informe completo del laboratorio sin avisos (idéntico a la V9 salvo propuesta aprobada), `npm run docs`. Informe: claves del catálogo, excepciones halladas y arregladas, cambios de texto.

### Celda: arte-ui
Eres Arte-UI. Lee `.claude/agents/arte-ui.md`. Sala: `Arte-UI`. Eres dueño de `theme.css`, `styles.css`, `campaign.css`, `card.ts`, `art.ts`, `glyphs.ts`, `engraving.ts`, `table.ts`, `runscreens.ts`, `guild.ts`, `widgets.ts`, `home.ts`, `lobby.ts`, `lupa.ts`, `rules-text.ts`, `flavor.ts`, `scripts/visual-qa.ts`, `qa.ts` y la parte de cliente de `src/shared/i18n/`.

1. **Catálogo de textos del cliente.** Cada texto visible, `data-tip`, `aria-label` y `title` del cliente sale del catálogo (`t(clave)`); el título sigue saliendo de `src/shared/brand.ts`. La QA falla si un nodo de texto visible no viene del catálogo.
2. **Seudolengua.** Un idioma de prueba `xx` (cada texto un 35 % más largo, con tildes y eñes) que se activa con `?lang=xx`. La QA visual corre los estados en las cuatro ventanas también en `xx`: cero recortes. Es la prueba de que se puede traducir sin rehacer pantallas.
3. **Accesibilidad.** Nombres accesibles y roles (`button`, `dialog`, `status`) en todos los controles; orden de tabulación igual al de lectura; `prefers-reduced-motion` respetado en todo; contraste AA (4,5:1) en todo texto y ≥ 7:1 en cifras y palos sobre crema; opción «Alto contraste» en Ajustes que sube placas y contornos sin cambiar la maquetación. La QA comprueba nombre accesible por control y el contraste de cada texto.
4. **Barrido** de todos los estados × 4 ventanas: cero P0 y P1. Anota los P2 que no arregles, con motivo.
5. **Rendimiento visual**: ninguna animación de `top`, `left`, `width` ni filtros; solo `transform` y `opacity`.

No añadas pantallas de juego. Comprobación: `npm run typecheck`, `QA_DIR=dist/qa-arte npm run forja` sin fallos y `QA_DIR=dist/qa-arte npm run qa:visual` con cero fallos, en español y en `xx`, dos veces seguidas; mira las capturas.

### Celda: juice-ux
Eres Juice-UX. Lee `.claude/agents/juice-ux.md`. Sala: `Juice-UX`. Eres dueño de `nav.ts`, `prompts.ts`, `main.ts` (teclas), `fx.ts`, `juice.css`, `audio.ts`, `whispers.ts`, `tutorial-ui.ts`, `platform.ts`, `net.ts`, `src/server/*`, `scripts/smoke.ts`, `scripts/gamepad-qa.ts` y, nuevo, `src-tauri/` y `scripts/empaquetar.ts`.

1. **Empaquetado con Tauri v2.** `src-tauri/` con la configuración mínima: ventana de 1280×800 que admite pantalla completa, icono desde `public/favicon.svg`, nombre desde `brand.ts`, sin permisos de red salvo el servidor de la conjura y la `telemetryUrl` consentida. `npm run empaquetar` construye el ejecutable de Windows y el de Linux (Steam Deck) a partir de `build:web`. Sin Steamworks: solo se deja el árbol listo para subir (carpeta `artifacts/empaquetado/` con los binarios y una nota de qué falta para Steam).
2. **Guardado en escritorio.** `platform.ts` detecta Tauri; el progreso sigue en las claves `derrumbe:*` del almacenamiento de la ventana. La copia de seguridad (`corona-rota-progreso-…json`, marcador `app: 'derrumbe'`) sirve para pasar el progreso de la web al escritorio y al revés.
3. **Steam Deck.** Mando como entrada principal, pantalla completa al arrancar, ningún enlace que abra el navegador sin aviso, texto ≥ 14 px a 1280×800.
4. **Rendimiento**: 60 fps con 4 jugadores en una máquina de gama baja (CPU del navegador limitada en `smoke.ts`, registro de fotogramas largos); carga inicial < 3 s; < 50 ms entre pulsación y primera respuesta en cada acción de `prompts.ts`.
5. **Defectos de entrada**: todas las pantallas con teclado y con mando, sin ratón; nada atrapa el foco; `B` y `Esc` siempre salen.
6. **Prueba de humo del escritorio**: `qa:smoke` corre también contra el ejecutable de Tauri (o su vista web con la marca de plataforma de escritorio si la máquina no puede abrirlo sin ventana) y da «Todo en orden».

No añadas mensajes de protocolo. Comprobación: `npm run typecheck`, `npm run empaquetar` y `QA_DIR=dist/qa-juice npm run qa:smoke` con «Todo en orden» dos veces seguidas, en web y en escritorio. Informe: tamaño de cada binario, fotogramas largos medidos, defectos arreglados y pendientes con motivo.

## 3. Criterios de aceptación

| # | Criterio | Orden |
|---|---|---|
| 1 | Cero identificadores añadidos o quitados respecto a la V9 | `npm test` |
| 2 | Cero textos visibles fuera del catálogo | `npm run qa:visual` |
| 3 | Seudolengua `xx` sin recortes en todos los estados × 4 ventanas | `npm run qa:visual` |
| 4 | Todo control con nombre accesible; contraste AA en todo texto, ≥ 7:1 en cifras y palos | `npm run qa:visual` |
| 5 | Cero P0 y P1, dos corridas seguidas | `npm run qa:visual` |
| 6 | Ejecutables de Windows y Linux construidos | `npm run empaquetar` |
| 7 | Humo en verde dos veces seguidas en web y en escritorio; foco nunca atrapado; 60 fps con 4 jugadores | `npm run qa:smoke` |
| 8 | Laboratorio sin avisos, P95 ≤ 19 e idéntico a la V9 salvo propuesta aprobada | `npm run analyze:meta` |
| 9 | Aprobación y claridad media sin bajar del margen respecto a la V9 | puerta de GPU |

## 4. Fuera de alcance

Cualquier función, reliquia, monarca, asalto, Reinado, palabra clave o sistema nuevo; cambios de números salvo una propuesta de autoajuste aprobada; cambios de protocolo; traducciones a otros idiomas (solo se prepara el catálogo); integración con Steamworks y subida a la tienda (solo se empaqueta). Lo que no quepa se anota como pendiente y no se mete.
